Count the code in a directory, a single file, a local git revision ('@v1.0', 'src@main'), or a
remote git repository URL ('https://github.com/owner/repo', 'git@github.com:owner/repo@v1.0'), or
compare what changed against another revision or baseline with 'diff', and return mezura's report
as text to read.

For each language: how many files, how many lines, how many of those lines are code, how many are
comments, its share of the total, and its size on disk. Each language with test code is split into
'production' and 'tests' rows under it, and under the total. Then the counts of what each language
declares (classes, structs, functions).

Only certain test code is found on its own: the markers a compiler reads (Rust's '#[cfg(test)]',
Java's and Kotlin's '@Test', C#'s '[Fact]' and '[Test]'), the names a toolchain defines ('_test.go',
Perl's '.t'), the directory a build tool compiles only for tests ('tests/' beside a Cargo.toml,
'src/test/' beside a pom.xml or a build.gradle), and the default test names of a test tool whose
own file is in a folder ('*.test.ts' and '__tests__/' under a jest.config.ts, 'spec/' under a
.rspec beside a Gemfile, 'test_*.py' under a conftest.py), which the report lists under 'Test
presets applied'. A language with no 'tests' row has none of those, so a Python, JavaScript, PHP,
Ruby or C++ project with no such file shows no tests until its convention is declared with
'tests', as a preset by name ('@pytest', '@jest', '@rspec') or as the patterns themselves
('test_*.py', '*.spec.ts', 'spec/'), which the project's own files say.

Answers questions like: how big is this project, what is it written in, how much of it is comments,
which language holds most of the code, which files are the longest.

Every file is read, so name the part of the tree that is actually wanted rather than the root of a
disk.
