Which language wins an extension that more than one of them claims, and which files wearing an
extension are not code at all.

Two languages can want the same extension: '.m' is Objective-C to one person and MATLAB to another,
'.pl' is Perl to one and Prolog to another. Only one of them can have it, and the choice matters more
than a label, because the wrong language means the wrong comment symbols, and then every comment line
of the loser is counted as code.

Without a line here, the extension goes to whichever language name comes first alphabetically, and
the program says so on every run so that it is never a silent decision. Write the extension, then the
languages that claim it separated by commas. The first name takes it and the rest lose their claim:

    m       Objective-C, MATLAB
    pl      Perl, Prolog

The names are the ones the language files declare, and neither they nor the extension care about
capitalisation. A language you have removed, or one that never existed, is skipped and the next name
on the line is tried.

Change who wins by reordering the names on a line, not by deleting the line. A copy you have not
edited is brought whole to each new version. An edited copy is merged: your contest lines are kept,
lines for extensions your copy does not mention are added, and your file as it stood is saved under
'replaced'. A line you removed is one your copy does not mention, so an update brings it back.

This file settles a contested file whose content says nothing. A language file may declare
'Identifying line starts' evidence, a line beginning with 'function' says MATLAB where one
beginning with '@interface' says Objective-C, and found evidence wins over the order written here;
'--no-heuristics' turns that reading off. To decide a contest outright for one run, or for one
project through its configuration file, use '--force-language', as in '--force-language m=matlab',
which overrides both the evidence and this file.

The four that ship are the only contests the shipped languages have between them, and none of the
four has an answer that is right for everybody:

  h     C Header over C++ Header and Objective-C, whose headers are also '.h' files. There is no way
        to tell them apart from the name. On GitHub, 55 of every hundred '.h' files are C, 36 are
        C++ and 9 are Objective-C, so a C++ project is the swap this line is most often wanted for.
  m     MATLAB over Objective-C. Both are common and neither is close to a majority: 59 of every
        hundred '.m' files on GitHub are MATLAB. Objective-C also answers to '.mm', so it still
        counts the part of a project that is not contested; MATLAB has no second extension at all.
  pl    Perl over Prolog. Prolog also answers to '.pro' and '.prolog'.
  pas   Pascal over Delphi. Delphi also answers to '.dpr' and '.dpk'.

A file known by its whole name, like 'Makefile' or 'CMakeLists.txt', is settled the same way, under
the second marker. Nothing that ships contests a name, so that block is empty and is there for the
languages you add:

    Makefile    Make, Automake

Some files carry a language's extension without being that language's code, or any code. Every
'.pro' of an Android project is a ProGuard configuration and not Prolog, and a build directory
fills with make and cargo dependency files ending in '.d' that are not the D language. The last
two markers hold, per extension, the give-away text of such files: a file whose head has a line
beginning with one of the first list's entries, or containing one of the second's, is left out of
the count and reported as skipped. '--count-not-code' turns this check off, and '--no-heuristics'
turns it off along with the rest. These marker lists belong to the program and are brought to what
each version ships; a line you add for an extension this file does not mention is kept.

Everything above is explanation and is ignored, exactly as in a configuration file. The rules
are the lines below each marker.
